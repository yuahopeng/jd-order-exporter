# 京东订单导出（本地）

把京东「我的订单」导出成 CSV —— **适配 2026 年改版后的新版订单页**。

数据全程只在你本机，不上传任何服务器。

---

## 为什么需要这个

2026 年京东改版了「我的订单」页面：**订单不再写进服务端返回的 HTML**，
而是页面加载后由前端 JS 动态填充。

这导致两类工具全部失效：

| 工具类型 | 为什么失效 |
|---|---|
| 早期浏览器扩展（如 `jd-order-exporter-extension` 等） | 它们「请求 HTML → 解析 DOM」，而请求回来的 HTML 里**一条订单都没有** |
| 基于 `order.jd.com/center/list.action?d=年份` 的爬虫 | 同上，应答体是空壳 |
| 依赖固定 class 的脚本 | 新版用 CSS Modules（`orderCard-b731ca` 这种带 hash 的类名），老选择器 `.td-void` 等全部失效 |

**本脚本的做法**：不请求 HTML，而是在**已经渲染完成的页面上**直接读取订单卡片，
并用 `[class*="orderCard-"]` 这类**前缀模糊匹配**抗住京东每次构建变化的 hash 后缀。

> 实测：2026-10 抓取某账号 2014–2026 全部订单，共 337 条，年份无缺口。

---

## 用法一：油猴脚本（推荐）

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 或 Violentmonkey
2. 新建脚本，粘贴 `jd-order-exporter.user.js` 全部内容并保存
   （或直接把 `.user.js` 文件拖进浏览器）
3. 打开 <https://order.jd.com/center/list.action>，确认已登录、能看到订单
4. 页面**右下角**会出现控制面板：

| 按钮 | 作用 |
|---|---|
| **抓取当前页** | 读取当前筛选条件下的所有页（自动翻页），按订单号去重后累积 |
| **导出累积全量** | 把累积到的全部订单导出成 CSV |
| **清空累积** | 清掉本地累积（重新开始） |

**跨年份收集的正确姿势**：

```
先在页面上手动筛选「2014 年」→ 点「抓取当前页」
切换成「2015 年」      → 再点「抓取当前页」
……（重复到最新年份）
最后点「导出累积全量」  → 得到一份含全部年份的 CSV
```

> 累积数据存在该页面的 `localStorage` 里，**跨年份、跨刷新都不丢**，不用一次抓完。

## 用法二：控制台脚本（不装油猴）

1. 打开订单页 → `F12` → 控制台（首次粘贴需先输入 `allow pasting` 回车）
2. 粘贴 `console-script.js` 的全部内容 → 回车
3. 脚本会自动翻页抓取当前筛选条件的**全部页**，然后直接下载 CSV
4. 切换年份后重跑；每次下载的 CSV 都是**累积全量**

## 导出的字段

`订单号` `下单时间` `店铺` `订单状态` `商品名称` `商品数量` `实付金额` `支付方式` `收货人` `收货地址` `抓取时间`

CSV 是 **UTF-8 带 BOM**，Excel / WPS 直接双击不乱码。

## 注意事项

- **先手动筛选年份**。时间筛选是 React 组件，脚本模拟点击不可靠，手动选最稳。
- **需要先登录**，且能正常看到订单列表。
- **限速**。脚本每页之间会等待，不要改成 0 延迟，翻太快可能触发风控。
- **收货人 / 地址可能为空**：虚拟商品（话费充值等）本来就没有收货信息，不是 bug。
- **金额是实付金额**，可能和订单页显示的「订单金额」不同（京豆 / 优惠券 / 运费险抵扣）。
- 类名会变。京东若再次改版，改的通常只是 class 前缀 —— 脚本里集中在前几行的选择器常量，便于修。

## 常见问题

**Q：抓到的 CSV 只有表头？**
A：说明页面上没有渲染出订单卡片。确认：① 已登录 ② 地址是 `order.jd.com/center/list.action`
③ 页面上确实能看到订单。

**Q：某个年份抓不到？**
A：可能已被京东划入超期数据（PC 端自动展示有时限）。可尝试京东 App 筛选该年份，
或拨打 950616 人工申请历史订单汇总。

**Q：翻页翻到一半停了？**
A：可能触发了风控。停 10 分钟再试，或手动翻页后分段抓取。

**Q：为什么不用请求接口的方式？**
A：新版订单接口（`api.m.jd.com`）需要 `h5st` 签名，逆向成本高且京东随时会改；
在渲染后的 DOM 上读取稳定得多，也不涉及伪造签名。
